# Task 1 Report: Project scaffold with the purity-scoped test project

## What I implemented

Transcribed the brief's Step 1–3 code blocks verbatim (no edits) into:

- `package.json` — scripts (`typecheck`, `lint`, `test`, `test:watch`; deliberately no
  `dev`/`build`/`preview`), devDependencies as specified.
- `tsconfig.json` — strict TS 5.9 config with `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, path alias `@/*` -> `src/*`.
- `vite.config.ts` — alias-only config, no entry points.
- `vitest.config.ts` — two Vitest projects: `app` (globals, node env, everything under
  `src/**/*.test.ts` and `test/**/*.test.ts` except `src/engine/reducer/**`) and
  `reducer-purity` (globals, node env, only `src/engine/reducer/**/*.test.ts`, with
  `setupFiles: ['./src/engine/reducer/purity.setup.ts']`).
- `eslint.config.js` — base flat config: `js.configs.recommended`,
  `tseslint.configs.recommended`, plus `consistent-type-imports` and `no-explicit-any`
  as errors. Ignores `dist`, `coverage`, `node_modules`.
- `src/engine/reducer/purity.setup.ts` — per-test `beforeEach`/`afterEach` stubs for
  `Math.random`, `Date` (constructor, call, and `.now`), `performance.now`, and
  `crypto.getRandomValues`/`crypto.randomUUID` (guarded by feature checks), each
  throwing a "Reducer purity violation" error citing spec §3.3. Restores previous
  property descriptors on teardown.
- `src/engine/reducer/purity.guard.test.ts` — 5 tests in the `reducer-purity` project
  confirming each stub throws with the expected message, and that `Date.UTC` (a
  non-clock static) remains reachable.
- `src/engine/purity-scope.test.ts` — 1 test in the `app` project confirming
  `Math.random`, `Date.now()`, and `new Date(0).toISOString()` all behave normally
  there, proving the guard is scoped to `reducer-purity` only.
